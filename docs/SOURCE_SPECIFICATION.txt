PROJECT: Student Portal Management System
TYPE: Full Stack Web Application (Apprentice/Academic Project)
PURPOSE: A production-ready student portal for managing academic 
         operations with role-based authentication and dashboards.

═══════════════════════════════════════════════════════════
TECH STACK — COMPLETE
═══════════════════════════════════════════════════════════

BACKEND:
  - Language      : Java 21
  - Framework     : Spring Boot 3.3
  - Security      : Spring Security 6 + JWT (jjwt 0.12.5)
  - ORM           : Spring Data JPA + Hibernate
  - Database      : MySQL 8
  - Build Tool    : Maven 3.9
  - API Docs      : Swagger / OpenAPI 3 (springdoc 2.5.0)
  - Mapping       : MapStruct 1.5.5
  - Boilerplate   : Lombok
  - Validation    : Jakarta Bean Validation
  - Testing       : JUnit 5 + Mockito + MockMvc + H2 (test profile)
  - Logging       : SLF4J + Logback

FRONTEND:
  - Framework     : Angular 20 (Standalone Components)
  - UI Library    : Angular Material 20
  - Language      : TypeScript 5.5
  - Forms         : Angular Reactive Forms
  - HTTP          : Angular HttpClient + Functional Interceptors
  - Routing       : Angular Router with Lazy Loading
  - State         : Angular Signals
  - Reactive      : RxJS 7.8
  - Styling       : SCSS + Angular Material Theming
  - Server        : Nginx (inside Docker container)

DATABASE:
  - Engine        : MySQL 8.0

  - Auditing      : Spring Data JPA Auditing
                    (createdDate, updatedDate, createdBy, updatedBy)
  - Test DB       : H2 in-memory (for unit/integration tests)

DEVOPS:

  - CI/CD         : GitHub Actions

═══════════════════════════════════════════════════════════
ARCHITECTURE
═══════════════════════════════════════════════════════════

BACKEND LAYERS:
  Controller Layer  → REST endpoints, request validation, HTTP codes
  Service Layer     → Business logic, transactions (@Transactional)
  Repository Layer  → Spring Data JPA, custom JPQL queries
  Entity Layer      → JPA entities, all extend BaseEntity
  Security Layer    → JWT filter, SecurityConfig, UserDetails
  Exception Layer   → GlobalExceptionHandler, custom exceptions
  DTO Layer         → Request/Response DTOs (separate from entities)
  Mapper Layer      → MapStruct mappers (Entity ↔ DTO)

FRONTEND LAYERS:
  features/         → Lazy-loaded page components (10 pages)
  core/services/    → HTTP API services (one per module)
  core/models/      → TypeScript interfaces matching backend DTOs
  core/guards/      → authGuard, roleGuard (functional)
  core/interceptors/→ authInterceptor (JWT), errorInterceptor
  shared/components/→ LayoutComponent (sidebar + toolbar)

DESIGN PATTERNS USED:
  - Repository Pattern (Spring Data JPA)
  - Service Layer Pattern (interface + impl)
  - DTO Pattern (decoupled API contracts)
  - Builder Pattern (Lombok @Builder on entities/DTOs)
  - Singleton Pattern (Spring beans, Angular services)
  - Guard Pattern (Angular route protection)
  - Interceptor Pattern (JWT injection, error handling)
  - Soft Delete Pattern (deleted flag, never hard delete)
  - Audit Trail Pattern (BaseEntity + AuditorAware)

ROLES AND ACCESS CONTROL
═══════════════════════════════════════════════════════════

ROLES (stored in DB, seeded on startup):
  ADMIN    → Full access to everything
  FACULTY  → Attendance, Marks, Reports, Announcements, Dashboard
  STUDENT  → View own profile, courses, attendance, marks, materials

DEFAULT CREDENTIALS (auto-seeded):
  Username : admin
  Password : Admin@123
  Role     : ADMIN

JWT IMPLEMENTATION:
  - Token Type    : Bearer
  - Algorithm     : HMAC-SHA (HS256 via jjwt)
  - Expiry        : 24 hours (86400000 ms, configurable)
  - Secret        : Base64-encoded, set via environment variable
  - Claims stored : username, role
  - Filter        : JwtAuthenticationFilter extends OncePerRequestFilter
  - Storage (FE)  : localStorage (sp_token, sp_user keys)

═══════════════════════════════════════════════════════════
DATABASE SCHEMA — ALL 10 TABLES
═══════════════════════════════════════════════════════════

BASE ENTITY (inherited by all tables):
  id            BIGINT AUTO_INCREMENT PK
  created_date  DATETIME
  updated_date  DATETIME
  created_by    VARCHAR(100)
  updated_by    VARCHAR(100)
  deleted       BOOLEAN DEFAULT false

TABLE: roles
  id    BIGINT PK
  name  VARCHAR(30) UNIQUE  → ADMIN | FACULTY | STUDENT

TABLE: users
  id        BIGINT PK
  username  VARCHAR(100) UNIQUE NOT NULL
  password  VARCHAR(255) NOT NULL  → BCrypt encoded
  email     VARCHAR(150) UNIQUE NOT NULL
  role_id   BIGINT FK → roles.id
  active    BOOLEAN DEFAULT true
  + BaseEntity columns

TABLE: students
  id           BIGINT PK
  roll_number  VARCHAR(50) UNIQUE NOT NULL
  first_name   VARCHAR(100) NOT NULL
  last_name    VARCHAR(100)
  email        VARCHAR(150) UNIQUE NOT NULL
  phone        VARCHAR(20)
  department   VARCHAR(100)
  semester     INT
  user_id      BIGINT FK → users.id (nullable, one-to-one)
  + BaseEntity columns

TABLE: courses
  id           BIGINT PK
  course_code  VARCHAR(30) UNIQUE NOT NULL
  course_name  VARCHAR(150) NOT NULL
  credits      INT NOT NULL
  faculty_name VARCHAR(100)
  + BaseEntity columns

TABLE: student_courses
  id          BIGINT PK
  student_id  BIGINT FK → students.id
  course_id   BIGINT FK → courses.id
  UNIQUE(student_id, course_id)
  + BaseEntity columns

TABLE: attendance
  id                     BIGINT PK
  student_id             BIGINT FK → students.id
  course_id              BIGINT FK → courses.id
  attendance_percentage  DECIMAL(5,2) NOT NULL
  UNIQUE(student_id, course_id)
  + BaseEntity columns

TABLE: marks
  id          BIGINT PK
  student_id  BIGINT FK → students.id
  course_id   BIGINT FK → courses.id
  score       DECIMAL(5,2) NOT NULL
  UNIQUE(student_id, course_id)
  + BaseEntity columns

TABLE: announcements
  id               BIGINT PK
  title            VARCHAR(200) NOT NULL
  description      VARCHAR(2000) NOT NULL
  created_by_name  VARCHAR(100)
  + BaseEntity columns

TABLE: study_materials
  id         BIGINT PK
  course_id  BIGINT FK → courses.id
  title      VARCHAR(200) NOT NULL
  file_url   VARCHAR(500) NOT NULL
  + BaseEntity columns

TABLE: audit_logs
  id        BIGINT PK
  action    VARCHAR(200) NOT NULL
  username  VARCHAR(100)
  + BaseEntity columns

ALL REST API ENDPOINTS (30+ endpoints)

  PUT    /api/courses/{id}            → Update course [ADMIN]
  DELETE /api/courses/{id}            → Soft delete [ADMIN]

  GET    /api/student-courses/student/{studentId}       → Student's courses
  GET    /api/student-courses/course/{courseId}         → Course's students

  DELETE /api/marks/{id}                    → Delete [ADMIN, FACULTY]
  GET    /api/marks/student/{id}            → Student marks

  POST   /api/announcements                 → Create [ADMIN, FACULTY]
  GET    /api/announcements/{id}            → Get by ID
  PUT    /api/announcements/{id}            → Update [ADMIN]
  DELETE /api/announcements/{id}            → Delete [ADMIN]

STUDY MATERIALS (CRUD):

RUNNING THE APPLICATION
═══════════════════════════════════════════════════════════

OPTION A — Manual (Development):

  1. Start MySQL:
     mysql -u root -p
     CREATE DATABASE student_portal;

  2. Start Backend:
     cd backend
     mvn spring-boot:run -Dspring-boot.run.profiles=dev
     → Runs on http://localhost:8080
     → Auto-creates all tables and seeds admin user

  3. Start Frontend:
     cd frontend
     npm install --legacy-peer-deps
     ng serve
     → Runs on http://localhost:4200

OPTION B — Docker Compose (One command):
  cp .env.example .env
  docker-compose up --build -d
  → MySQL:    localhost:3306
  → Backend:  http://localhost:8080
  → Frontend: http://localhost:80

  Username: admin
  Password: Admin@123

═══════════════════════════════════════════════════════════
BUSINESS LOGIC HIGHLIGHTS
═══════════════════════════════════════════════════════════

GRADE CALCULATION (automatic in MarksService):
  Score >= 90  → A+
  Score >= 80  → A
  Score >= 70  → B+
  Score >= 60  → B
  Score >= 50  → C
  Score >= 40  → D
  Score < 40   → F

ATTENDANCE DEFAULTER THRESHOLD:
  Below 75% → flagged as defaulter

ATTENDANCE BANDS:
  Excellent → >= 90%
  Good      → 75% to 89%
  Average   → 50% to 74%
  Poor      → < 50%

PASS/FAIL THRESHOLD:
  Score >= 40 → PASS
  Score < 40  → FAIL

AT-RISK STUDENT DETECTION:
  Low attendance (< 75%) AND/OR low marks (< 40 avg)
  Shows reason: "Low attendance", "Low marks", or both

SOFT DELETE:
  No records are ever hard deleted from the database
  All deletes set deleted=true
  All queries filter WHERE deleted=false

AUDIT LOGGING:
  Every create/update/delete/login/register action
  is recorded in audit_logs table automatically
  with action name and username
